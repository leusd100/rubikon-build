# Phase 6 — Візуальна система Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Зібрати ізольоване візуальне прев’ю п’яти сторінок напрямів у стилі «Креслярський аркуш», щоб власник міг оцінити його до будь-якого PR.

**Architecture:** Залишити п’ять наявних адаптивних зображень героя як фонову основу й незмінне джерело зображення для Service JSON-LD. Додати окремий декоративний SVG-шар з п’ятьма різними композиціями; повторно використати наявні схеми для металу, бетону й покрівлі, а для ангарів і зерносховищ створити абстрактний ритм без інженерних розмірів чи тверджень. Під’єднати шар у спільному герої сторінок напрямів; відеокомпоненти HOME та «Про нас» не зачіпати.

**Tech Stack:** Next.js, React, TypeScript, SVG, CSS variables і media queries у наявній темі.

**Spec:** `docs/superpowers/specs/2026-10-13-phase6-visual-system-design.md`

## Global Constraints

- Не змінювати відео та цілі відеоблоки HOME і «Про нас».
- Не змінювати бізнес-твердження, фактичний зміст, інженерні числа чи обіцянки.
- Схематичні зображення залишаються явно концептуальними: без розмірів, масштабу чи вигляду підтвердженого проєктного креслення.
- Зберігати наявні responsive-зображення, їх пріоритет завантаження, alt-поведінку та зображення в Service JSON-LD.
- Використовувати наявну палітру, шрифти й графітову гаму; мідний акцент — лише для одного значущого елемента композиції.
- Усі ключові стани переглянути на 390×844, 768×1024, 1250×613 і 1440×900 у світлій і темній темах.
- Для руху зберегти нерухомий кінцевий стан при `prefers-reduced-motion`.
- Не оновлювати візуальні еталони до окремого погодження `visual-freeze`; прев’ю саме по собі не дозволяє PR, merge чи deployment.

## Review Focus

- Мобільний перший екран: H1 і головна дія мають лишатися видимими, SVG не має накривати текст — ручний перегляд усіх п’яти сторінок при 390×844.
- Планшетна композиція: ілюстрація має зберігати власний характер без надмірного зменшення текстової колонки — перегляд при 768×1024.
- Низький desktop viewport: герой і кнопки не мають обрізатися на 1250×613; перевірити ангар, зерносховище та покрівлю з найдовшими назвами/текстом.
- Контраст тем: графітові лінії, підписи й мідний акцент лишаються читабельними в обох темах; жодна важлива відмінність не передається лише кольором.
- Стан без анімації та семантика: при reduced motion показується завершений SVG, декоративний шар не потрапляє до дерева доступності, а Service JSON-LD продовжує посилатися на чинний hero image.

### Task 1: Створити п’ять креслярських композицій героя

**Files:**
- Create: `app/components/directions/DirectionHeroDrawing.tsx`
- Read/reuse: `app/components/directions/DirectionSectionDrawing.tsx` — наявні `Steel`, `Concrete`, `Roofing` компоненти

**Interfaces:**
- Consumes: `DirectionPageConfig['id']` як ідентифікатор одного з п’яти напрямів.
- Produces: `DirectionHeroDrawing({ id }: { id: DirectionPageConfig['id'] })), декоративний SVG-шар із `aria-hidden="true"` і `focusable="false"`.

- [ ] **Step 1: Додати SVG-композиції для `angary` і `zernoskhovyshcha`.** Використати повторюваний ритм рам для ангарів та вертикальний ритм ємностей для зерносховищ; лишити їх абстрактними, без розмірів, чисел і специфікацій.
- [ ] **Step 2: Зібрати карту п’яти напрямів.** Для `metalokonstruktsii`, `betonni-roboty` і `pokrivelni-roboty` повторно використати відповідно `Steel`, `Concrete`, `Roofing`; для кожного напряму задати власну SVG-композицію в одному узгодженому `viewBox`.
- [ ] **Step 3: Провести візуальний огляд композицій окремо від сторінки.** Переконатися, що лінії не утворюють непідтверджених інженерних деталей, а мідний акцент один і локальний; внести виправлення до компонента.

### Task 2: Під’єднати шар до спільного героя напрямів

**Files:**
- Modify: `app/components/DirectionDetail.tsx` — `DirectionHero` та його виклик у `DirectionPage`
- Read/preserve: `app/components/DirectionHeroImage.tsx`
- Read/preserve: `app/data/directionHeroImageManifest.ts`

**Interfaces:**
- Consumes: `DirectionHeroDrawing({ id })` із Task 1 та поточний `config.id`.
- Produces: спільний `service-subhero`, що показує напрямо-специфічний SVG поверх наявної композиції зображення.

- [ ] **Step 1: Передати `config.id` до `DirectionHero`.** Додати типізований проп `directionId: DirectionPageConfig['id']` і передавати його з `DirectionPage`.
- [ ] **Step 2: Вмонтувати SVG окремим декоративним шаром у `service-subhero-media`.** Залишити `DirectionHeroImage`, її srcSet/focal points, `loading="eager"`, `fetchPriority="high"`, `alt=""` і Service JSON-LD `image` без зміни.
- [ ] **Step 3: Переглянути всі п’ять маршрутів.** Переконатися, що візуальна композиція не змінює копірайт, дії, breadcrumbs, provenance-мітку «Ілюстрація» або розмітку Service.

### Task 3: Оформити адаптивність, теми та безпечний рух

**Files:**
- Modify: `app/components/directions/direction-template.css`
- Read/preserve: наявні CSS-змінні теми та правила `prefers-reduced-motion`

**Interfaces:**
- Consumes: SVG-шар із Task 1, розташований у герої згідно з Task 2.
- Produces: читабельне розміщення на чотирьох визначених viewport-ах і завершений статичний стан.

- [ ] **Step 1: Додати позиціювання SVG для широкого героя.** На desktop розмістити креслення як виразний, але другорядний шар поруч із текстом; воно не перехоплює кліки, не перекриває H1 чи кнопки.
- [ ] **Step 2: Додати адаптивні стани.** На вузькому екрані зменшити або приховати фонові слова/великі номери, зберегти видимість H1 і дії; узгодити розташування з поточним кадруванням зображення.
- [ ] **Step 3: Додати кольори через наявні theme tokens.** Графітові лінії мають читатися в light/dark; мідь підсвічує лише один елемент; підписи креслення декоративні й не несуть критичного змісту.
- [ ] **Step 4: Застосувати рух тільки якщо він пояснює послідовність побудови ліній.** У `prefers-reduced-motion: reduce` показати завершений SVG без transition/animation; за вимкненого JavaScript герой також має лишатися видимим.
- [ ] **Step 5: Зробити ручний візуальний прохід.** Перевірити всі п’ять маршрутів на 390×844, 768×1024, 1250×613 і 1440×900 у light/dark та reduced-motion. Порівняти з поточним виглядом; не оновлювати snapshots.
- [ ] **Step 6: Підготувати прев’ю для перегляду власником.** Зібрати посилання або знімки «до / після» для кожного напряму й розміру; зупинитися перед `visual-freeze`, PR, merge або deployment до окремого рішення власника.
