# DebugBear — експорт історії перед завершенням підписки (27.10.2026)

Підписка DebugBear (проєкт `108814`) завершується 27.10.2026. Тут збережено все, що мало цінність і що API віддає:
щоденні синтетичні прогони всіх 21 сторінки за весь період моніторингу та повні Lighthouse-звіти, з якими
можна порівнювати майбутні зміни. Експорт зроблено через DebugBear MCP; зібрав Claude Code.

## Що є

| Файл | Що всередині | Розмір |
|---|---|--:|
| `pages.csv` | 21 моніторена сторінка: `pageId`, шлях, пристрій, кількість прогонів, перший і останній прогін | 2 КБ |

Назва Lighthouse-файлу: `<сторінка>-<mobile|desktop>-<latest|first>-<дата>-<analysisId>.json.gz`.

Регіон — Польща, розклад — раз на 24 год (частину сторінок у дні релізів тестували частіше вручну).
Це **жорсткіший мобільний профіль**, ніж Lighthouse CI репозиторію (`lighthouserc.cjs`, локальний сервер без CDN) —
числа між собою напряму не порівнюються.

## Чого немає і чому

- **RUM** — не був підключений (`get_rum_metrics` порожній за весь період).
- **CrUX (поля)** — колонки `crux.*` порожні: у Chrome UX Report недостатньо трафіку rubikonbuild.com ні на рівні URL, ні origin. Єдине джерело правди про швидкість зараз — синтетичні прогони.
- **Анотації** — у проєкті їх не було.
- **Окремі waterfall-и запитів** — не вивантажені: ті самі дані є в аудиті `network-requests` кожного Lighthouse JSON.
- **Скриншоти** — з Lighthouse JSON вирізано (`screenshot-thumbnails`, `full-page-screenshot`, `final-screenshot` — base64, ~230 КБ на звіт). Візуальний контроль у нас — Playwright-еталони.
- **Перші прогони** для решти 15 сторінок — не вивантажені: їхні метрики є в CSV, повний звіт дає мало понад це.

Висновки:

1. **Мобільна головна — найслабша сторінка з найбільшою вагою для бізнесу**: Performance 0.72 за 14 днів без руху, TBT 620 мс,
   LCP ~3,5 с. Підчастини LCP (останній звіт): TTFB 554 мс, затримка завантаження 125 мс, **завантаження 2841 мс**,
   рендер 48 мс. LCP-зображення (`hero-line-concept-v3-1024w.webp`, 118 КБ, уже `fetchpriority=high`) ділить канал 1,6 Мбіт/с
   із 6 передзавантаженими шрифтами (+2 Manrope), ~45 JS-чанками і 117-КБ `hangar-retouched-1536w.webp` (lazy, але в межах
   порогу lazy-load на повільній мережі, тож вантажиться паралельно з LCP).
2. **Сторінки напрямів на мобільному покращилися вдвічі** (LCP ~4,8–5,5 с → ~2,1–2,5 с; оцінка 0.56–0.76 → 0.81–0.93) після
   робіт 13–24.10 (мобільні герої, responsive poster).
3. **`/pro-nas` mobile: LCP 1,97 → 3,09 с — не регресія коду**, а наслідок дизайн-рішення #243 (єдині мобільні герої): LCP-елемент
   змінився з тексту `<p>` (обмеження — рендер, 1374 мс) на ілюстрацію (обмеження — завантаження, 2528 мс). TBT при цьому впав 479 → 134 мс.
4. **Шрифти — 155–205 КБ на кожній сторінці** (8 файлів, 6 із них `preload`). Це свідоме рішення (без зсуву героя,
   `app/layout.tsx`, `direction-static-hero.spec.ts`), але на мобільному профілі саме воно конкурує з LCP-зображенням.
   Кандидат для окремого рішення власника, не для тихої оптимізації.
5. **Desktop `/` і `/pro-nas` — ~4 МБ** через автопрогравання відео героя — у межах свідомого бюджету 6 МБ для головної (`lighthouserc.cjs`).
6. **CLS 0.000 на всіх 21 сторінці за весь період.**
7. Дублікат: сторінки `767236` (`https://rubikonbuild.com`) і `767238` (`https://rubikonbuild.com/`) — один і той самий desktop-URL.
