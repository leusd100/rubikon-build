# Лабораторія продуктивності

## Базова лінія

- **Production до 27.10** — `docs/performance/debugbear-2026-10-27/` (21 сторінка, 485 прогонів, Lighthouse JSON). RUM і CrUX
  відсутні: трафіку замало, тож поля CrUX порожні.
- **Production з 22.11** — DebugBear, проєкт `110361`: 10 маршрутів × Mobile/Desktop, раз на 12 год, Польща, ті самі профілі
  (Mobile: RTT 150 мс, 1,6 Мбіт/с, CPU ×4, 412×660 @2,625; Desktop: RTT 40 мс, 8 Мбіт/с, CPU ×1). Базова лінія — медіана
  ≥ 6 прогонів, не один прогін: розкид між прогонами — сотні мілісекунд. Читання — DebugBear MCP; запис і тести, що
  витрачають кредити (`analyze_page`, `run_experiment`, анотації, бюджети), — лише з OK власника.
- **Production після 27.10** — `pagespeed-monitor.yml`: HOME після кожного деплою; щодня по сторінці на шаблон (артефакт
  `pagespeed-*`, Step Summary). PSI — Lighthouse 13, симульоване тротлінгування.
- **Бюджет-воротар** — `pnpm test:lighthouse` (Nightly, `lighthouserc.cjs`): Lighthouse 12.6, simulate, 5 прогонів, медіана, по
  HTTP/2 (`lhci-server.mjs --http2`). Лабораторні команди нижче йдуть по HTTP/1.1: їхні числа з бюджетами не порівнюй.

## Локальний вимір (до і після — однаково)

```bash
pnpm build
node scripts/perf/lhci-server.mjs --port 4174 &        # brotli, як у Cloudflare
node scripts/perf/lab-lighthouse.mjs --url http://127.0.0.1:4174/ --runs 5 --throttling devtools
node scripts/perf/lab-lighthouse.mjs --url http://127.0.0.1:4174/ --runs 5                      # simulate = як Nightly
node scripts/perf/trace-style-layout.mjs --url http://127.0.0.1:4174/ --runs 5 [--invalidation]
```

- `devtools` = справжнє сповільнення Chrome на екрані DebugBear (412×660 @2,625) з **каліброваним** профілем (150 мс на запит,
  1,6 Мбіт/с, CPU ×4): сума LCP HOME збіглася з production (3574 vs 3568 мс), частини — ні (тут немає TTFB). Це не модель
  DebugBear: він сповільнює пакети, а перерахунок Lighthouse на запити (562,5 мс) дав тут 8,5 с — HTTP/1.1-сервер змушує ~66 запитів
  чекати на шести з'єднаннях. Порівнюй гілку з `main` на одній машині, не з production.
- 5 прогонів, медіана. Дві збірки одночасно — різні порти (`--port 4274` …; апстрім займає порт +1000).
- Зупиняй сервер за портом — лише того, хто слухає: `lsof -ti tcp:4174 -sTCP:LISTEN | xargs -r kill`.

## Уже перевірено — не повторюй без нового доказу (27.10, HOME mobile)

| Гіпотеза | Експеримент | Результат |
|---|---|---|
| Прибрати примусові перерахунки стилю (`useRoom`, `ProcessMotion`) зменшить TBT | правка + 5×5 трейсів | forced 239 → 157 мс, але стиль+розкладка 783 → 791 мс, блокування 775 → 756 мс (шум). **Відхилено**: перший перерахунок після гідратації платить той, хто першим читає розкладку |
| `body:has(...)` змушує перераховувати все дерево | нейтралізовано в одноразовій збірці | 780 мс проти 783 мс. **Відхилено** |
| LCP-зображення чекає за ~45 модульними скриптами (TTFB зображення 900 мс у production) | лише з waterfall DebugBear | **Не перевірено**: локальний HTTP/1.1 не відтворює HTTP/3-пріоритети Cloudflare; потрібен вимір на preview (OK власника) |
| «Improve image delivery»: фото героя HOME 1024w має «178 КБ зайвих» (22.11, mobile) | розрахунок з Lighthouse 13.5 `image-delivery-insight` | **Хибне спрацювання**: інсайт ділить на показані CSS-пікселі без DPR. 412×618 @2,625 потребує 1082×1622 px — більше за 1024×1536. Те саме на 6 інших mobile-сторінках |
| Фото героя сторінок напрямів стартує лише після останнього CSS (22.11): тег `<script>` теми в `<picture>` ховає його від preload-сканера, а 4 вбудовані скрипти в `<head>` після CSS тримають парсер | локальна A/B на production, 2 × (3+3), 1,6 Мбіт/с / 150 мс / CPU ×4: тег прибрано | **Механізм підтверджено, виграш малий**: фото стартує о 0,1–0,3 с замість ~2,2 с, але приходить майже тоді ж (смуга спільна); `/napryamky` LCP −0,4…−0,6 с при FCP +0,1…+0,3 с, `/zernoskhovyshcha` FCP +0,16 с |

Відоме, але не «тиха оптимізація» (рішення власника): 6 передзавантажених шрифтів (~125 КБ) конкурують з LCP-зображенням на
мобільному — свідомий вибір проти зсуву героя (`app/layout.tsx`).

## Звіт

Таблиця «до / після» з методом, медіаною й кількістю прогонів; відхилені гіпотези — теж. Не оновлюй `lighthouserc.cjs` і
не послаблюй бюджети: це рішення власника.
