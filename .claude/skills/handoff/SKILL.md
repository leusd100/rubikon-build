# Handoff: усе, що наступна сесія і власник мають знати, — у репозиторії

Файл `docs/handoffs/YYYY-MM-DD-<тема>.md` комітиться **на гілку PR**. Зображення — `docs/handoffs/media/<тема>/`.
Репозиторій публічний: без приватних шляхів, токенів, листування, особистих даних.

Наступна сесія починає з цього файлу і `git log origin/main..HEAD`; приватні `DECISIONS.md` / `CURRENT_CHECKPOINT.md`
(rubikon-control) вона не бачить. Тож усе потрібне для продовження — тут, а оновлення тих файлів лише **пропонуються**
окремим розділом.

## Шаблон

```markdown
# Handoff · <людська назва> (<ID-и>)

| | |
|---|---|
| Дата | YYYY-MM-DD |
| Виконавець | Claude Code |
| Підстава | <рішення власника з датою та ID; або доказ, з якого почалася задача> |
| PR | [#N](https://github.com/leusd100/rubikon-build/pull/N), Draft. **Merge і production deploy — лише з окремого OK Дмитра** (DEC-30) |
| Гілка / base | `<гілка>` від `main` `<sha>` |
| Коміти | `<sha>` — що · `<sha>` — що |
| Змінено | <файли й суть> |
| Не змінено | <що свідомо не чіпали: дизайн, тексти, еталони, бюджети, залежності> |

## Що було
<проблема з числами «до» і як їх отримано (команда, прогін)>

## Що зроблено
<рішення; відхилені гіпотези — з цифрами, щоб їх не перевіряли вдруге>

## Перевірка
| Перевірка | Команда / прогін | Результат |
|---|---|---|

## Еталони
<не змінювались | які саме, з якого артефакту CI, з чийого OK (DEC-18)>

## Успадковані червоні перевірки
<що червоне й на main, з посиланням; або «немає»>

## Ризики
## Що перевірити власнику
## Відкат
<найшвидший безпечний відкат>

## Пропоновані оновлення control (лише після OK)
<рядки для DECISIONS / CURRENT_CHECKPOINT, якщо є>
```

Порожній розділ лишай з «немає» — так видно, що його перевірили. Числа — з одиницями й методом виміру.
